<task type="auto">
  <name>Create API call detector</name>
  <files>src/analyzer/mocks/detector.ts</files>
  <action>
    Create src/analyzer/mocks/detector.ts that:
    - Exports function detectApiCalls(steps: RecordingStep[]): ApiCallInfo[]
    - Scans recording steps for indicators of network activity:
      - URL patterns in step selectors/values (http://, https://, /api/, /graphql)
      - Wait steps that might indicate network delays
      - POST/PUT/GET mentions in notes or selectors
    - Returns array of ApiCallInfo:
      interface ApiCallInfo {
        stepIndex: number;
        url: string;
        method: 'GET' | 'POST' | 'PUT' | 'DELETE' | 'PATCH';
        requestBody?: any;
        responseType?: 'json' | 'html' | 'text';
        timing: 'before' | 'after' | 'during';
      }

    Detection patterns:
    - URLs in selectors: matches(/https?:\/\/[^\s]+/i)
    - API path segments: matches(/^\/api\/|\/graphql$/)
    - Wait with network: step.type === 'wait' && step.selector?.includes('api')
  </action>
  <verify>npm test -- --grep "detectApiCalls" passes</verify>
  <done>detectApiCalls returns array of identified API calls</done>
</task>

<task type="auto">
  <name>Create mock target analyzer</task>
  <files>src/analyzer/mocks/target-analyzer.ts</files>
  <action>
    Create src/analyzer/mocks/target-analyzer.ts that:
    - Exports function analyzeMockTargets(apiCalls: ApiCallInfo[], projectPath: string): Promise<MockTarget[]>
    - Scans codebase for:
      - Existing mock files (src/**/*mock*, src/**/*fixture*)
      - Mock library usage (msw, jest.mock, sinon)
      - API service files that could be mocked
    - Returns MockTarget[]:
      interface MockTarget {
        name: string;
        type: 'fetch' | 'xhr' | 'module' | 'service';
        library: 'msw' | 'jest' | 'sinon' | 'none';
        filePath?: string;
        handler?: string;
        inline: boolean; // true = inline mock, false = import mock
      }

    Decision logic for inline vs extract (MOCK-03):
    - If mock used in >3 tests → extract to shared file
    - If mock is simple (return value) → inline
    - If mock has complex logic → extract
    - User can override via instructions
  </action>
  <verify>npm test -- --grep "mockTargets" passes</verify>
  <done>analyzeMockTargets returns mock targets with library recommendations</done>
</task>

<task type="auto">
  <name>Create mock code builder</name>
  <files>src/generator/mocks/builder.ts</files>
  <action>
    Create src/generator/mocks/builder.ts that:
    - Exports function buildMock(target: MockTarget, response?: any): MockCode
    - Generates appropriate mock code based on library:

    interface MockCode {
      code: string;
      imports: string[];
      placement: 'inline' | 'top-of-file' | 'separate-file';
    }

    For MSW:
    - Generate http.get('/api/users', ...) { json(userList) }
    - Generate http.post('/api/users', ...) { json(newUser) }

    For Jest:
    - Generate jest.spyOn(fetch).mockResolvedValue(...)
    - Generate jest.mock('...', () => (...))

    For inline:
    - Generate const mockFetch = jest.fn()...

    For extracted:
    - Generate import { mockFetch } from '../mocks/api'

    Response handling:
    - If recording captured response → use it
    - If no response → generate with TODO comment for user to fill
  </action>
  <verify>npm test -- --grep "buildMock" passes</verify>
  <done>buildMock generates valid mock code for msw/jest/sinon</done>
</task>
