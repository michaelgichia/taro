**Exports interface:**
```typescript
export interface QuerySelectorCall {
  selector: string
  line: number
}

export interface JsParseResult {
  title: string
  environmentUrl: string | undefined
  steps: NormalizedStep[]        // all steps, targets are RTL query strings or raw CSS selectors
  querySelectorCalls: QuerySelectorCall[]  // CSS selectors needing Playwright resolution
  itGroups: ItGroup[]            // steps segmented by modal boundary
}
```

**`classifyQuery(method: string): QueryQuality`:**
Use a static map object (not switch):
```
getByRole → 'excellent'
getByLabelText → 'excellent'
getByAltText → 'excellent'
getByTitle → 'acceptable'
getByText → 'good'
getByDisplayValue → 'acceptable'
getByPlaceholderText → 'acceptable'
getByTestId → 'fragile'
default → 'fragile'
```

**`extractEnvironmentUrl(code: string): string | undefined`:**
Regex match `@jest-environment-options\s*(\{[^}]+\})`, JSON.parse the capture group, return `parsed.url` if string. Return undefined on parse failure (no throw).

**`segmentIntoItGroups(steps: NormalizedStep[]): ItGroup[]`:**
Implement the modal boundary algorithm from RESEARCH.md Pattern 5:
- Iterate steps; maintain `current: NormalizedStep[]` accumulator
- Boundary condition: `step.action === 'click'` AND `next?.action === 'assert'` AND `next.target` exists AND `next.target.toLowerCase().includes(step.target?.toLowerCase() ?? '')`
- Apply stricter check from pitfall 4: NO `navigate` step between click and assert (skip boundary if steps between them include navigate); heading must appear within 1-2 steps of click
- When boundary found: push `{ name: step.target ?? 'flow', steps: current }`, reset accumulator
- Final remaining steps form last group
- If no boundaries found: return `[{ name: 'recorded flow', steps }]`
- Return `[]` only if `steps` is empty

**`parseJsRecording(code: string): Promise<JsParseResult>`:**
1. Validate: if code starts with `{` (JSON), throw `Error('Expected JS file from Testing Library Recorder extension. Got JSON — use the Chrome Recorder JSON parser instead.')`
2. Call `extractEnvironmentUrl(code)` to get the URL
3. Use `@babel/parser` with `sourceType: 'commonjs'` and `parse(code, { ...options })`
4. Use `@babel/traverse` (ESM interop: `const traverse = (_traverse as any).default ?? _traverse`) to walk the AST
5. Visitor: collect all `CallExpression` nodes:
   - `screen.getBy*` → extract method name, first argument (string literal or regex), build NormalizedStep with `action: 'click'` (user interaction context) or `action: 'assert'` — for Phase 3 keep it simple: all screen calls become `action: 'assert'`, target = query string
   - `document.querySelector(...)` → extract CSS selector string, add to `querySelectorCalls`
   - `userEvent.*` calls → map to appropriate NormalizedAction: `click`, `fill`, `type`, `keyboard` → `keyDown`, `selectOptions` → `select`
   - `await page.goto(url)` → `action: 'navigate'`, target = URL string
6. Extract title from the file's leading comment or first string literal matching the recording title format; sanitize: strip ` at HH:MM:SS` date suffix, replace hyphens with spaces
7. Return `JsParseResult` (immutable — no mutation)

**ESM interop guard (CRITICAL — apply in all files using @babel/traverse):**
```typescript
import _traverse from '@babel/traverse'
const traverse = (_traverse as any).default ?? _traverse
```

- Do not mutate step arrays — use spread/map
- Do not use `require()` syntax in this TS file (project is ESM)
