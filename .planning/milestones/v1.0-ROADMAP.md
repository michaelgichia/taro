# Milestone v1.0: Regrade a test directory

**Status:** ✅ SHIPPED 2026-03-31 **Phases:** 1-8 **Total Plans:** 12

## Overview

Add `regrade --directory-loop` so Taro can batch regrade every eligible test in a directory, persist score-history updates safely, surface progress in a canonical Markdown tracker, and document the workflow across shipped runtime surfaces.

## Milestone Summary

**Decimal Phases:**

- None.

**Key Decisions:**

- Reused the existing directory-loop tracker abstraction instead of creating a second batch progress system.
- Kept directory-loop regrade sequential so tracker and `.taro/state.json` writes remain deterministic.
- Solved the audit gap with formal verification backfill phases instead of reopening shipped product code.

**Issues Resolved:**

- Added a hidden `__regrade` directory-loop command path for internal runtime routing.
- Preserved score-history matching and latest-5 trimming while extending regrade to batch mode.
- Closed all 14 audit blockers by adding verification evidence and approved Nyquist sign-off.

**Issues Deferred:**

- Configurable score-threshold requeueing remains future work.
- Aggregate regrade delta export remains future work.
- Parallel batch regrading remains out of scope.

**Technical Debt Incurred:**

- Runtime surfaces are covered by automated asset/package tests rather than live multi-agent sessions.
- Some verification evidence relies on scoped Vitest commands because broader wrappers pull unrelated suites.
