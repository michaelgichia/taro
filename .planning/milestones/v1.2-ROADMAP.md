# Milestone v1.2: Runtime Installer Distribution

**Status:** ✅ SHIPPED 2026-03-07
**Phases:** 10-12
**Total Plans:** 10

## Overview

v1.2 turned `@tayo-dev/rtl` into an installer-first package that bootstraps Tayo into Claude Code, OpenCode, Gemini CLI, and Codex from one command. The milestone shipped the interactive and non-interactive installer flow, runtime-native packaged assets, safe reruns and repair behavior, verified runtime help commands, and installer-first release documentation.

## Phases

### Phase 10: Installer Core & Package Entry

**Goal**: Users can invoke `@tayo-dev/rtl` as an installer, choose runtimes and install location, and get a deterministic install plan without yet depending on runtime-specific payload implementation details
**Depends on**: Phase 9
**Plans**: 3 plans

Plans:

- [x] 10-01: Installer-first root CLI and explicit `install` command
- [x] 10-02: Runtime-first interactive flow and non-interactive flag normalization
- [x] 10-03: Install-plan model, prewrite summary, and confirmation flow

**Details:**
- Running `npx @tayo-dev/rtl@latest` now enters an installer flow instead of generator-only help.
- The installer accepts `--claude`, `--opencode`, `--gemini`, `--codex`, `--all`, `--global`, and `--local` combinations without prompting.
- Global vs local targets are modeled explicitly and summarized before writes occur.
- `@tayo-dev/rtl` remains the only installer package; `tayo generate` stays available as a preserved subcommand.

### Phase 11: Runtime Targets & Asset Delivery

**Goal**: Each supported runtime receives the correct packaged assets and a working runtime-native help entrypoint
**Depends on**: Phase 10
**Plans**: 4 plans

Plans:

- [x] 11-01: Runtime registry, manifest, and package asset foundation
- [x] 11-02: Prompt-runtime assets and temp-directory delivery tests
- [x] 11-03: Codex skill suite and temp-directory delivery tests
- [x] 11-04: Real write execution, conflict handling, and all-runtime reporting

**Details:**
- Claude Code and Gemini CLI installations expose `/@tayo-dev/rtl:help`.
- OpenCode installations expose `/@tayo-dev/rtl-help`.
- Codex installations create `skills/@tayo-dev/rtl-*/SKILL.md` assets and expose `$@tayo-dev/rtl-help`.
- `--all` installs all supported runtimes in one run, writes manifests and ownership markers, and reports per-runtime verification commands.

### Phase 12: Verification, Updates & Release Docs

**Goal**: Installer reruns are safe, verification commands are trustworthy, and the README documents the real shipped onboarding flow
**Depends on**: Phase 11
**Plans**: 3 plans

Plans:

- [x] 12-01: Repair and update semantics for safe reruns
- [x] 12-02: Runtime verification helpers and tarball smoke proof
- [x] 12-03: Installer-first README and release docs

**Details:**
- Re-running the installer updates or repairs owned assets without manual cleanup.
- Install completion output includes trustworthy verification commands for each selected runtime.
- The README documents interactive install, non-interactive install, staying updated, and development installation using the real package entrypoint.
- Release verification proved that the published tarball contains `dist`, runtime assets, and the README content needed by the installer flow.

## Milestone Summary

**Decimal Phases:**

- None

**Key Decisions:**

- Decision: Keep `@tayo-dev/rtl` as the single installer package rather than introducing a separate umbrella package.
- Decision: Preserve `tayo generate` while making the package root installer-first.
- Decision: Treat Codex as skills-first and install namespaced `skills/@tayo-dev/rtl-*` directories instead of prompt files.
- Decision: Use explicit ownership manifests and visible markers so reruns can refresh and repair owned assets while protecting manual edits.

**Issues Resolved:**

- Replaced generator-first package entry behavior with a real installer-first onboarding flow.
- Shipped runtime-native assets for Claude Code, Gemini CLI, OpenCode, and Codex from the published package.
- Added conflict handling, rerun repair semantics, verified runtime commands, and tarball proof for release confidence.

**Issues Deferred:**

- No separate `v1.2` milestone audit artifact was created before archival; closeout proceeded because all 13 requirements, all 10 plans, and Phase 12 verification were complete.
- Runtime uninstall/cleanup flow remains future work.
- Installer diagnostics/doctor flow remains future work.

**Technical Debt Incurred:**

- Product identity still mixes installer-first `@tayo-dev/rtl` branding with the historical `tayo generate` command.
